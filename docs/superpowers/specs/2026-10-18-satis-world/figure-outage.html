The agent on the game PC sends ●snapshots to the backend one at a time, oldest first. Anything it can't deliver yet waits in its ⬬queue. If something along the way is down, an ●error comes back; the agent keeps that snapshot and tries again later, waiting a little longer each time.

When the link breaks, something has to give. The system picks availability: the dashboard keeps answering with the last snapshot it has, marked stale, rather than going blank, and the agent keeps collecting. The cost is consistency: history arrives late, and if the outage outlasts the queue, the oldest readings are ○dropped for good. For a live dashboard, the newest data matters most.

Goals
  • Take the backend down and watch snapshots wait in the queue.
  • Keep it down until a snapshot is dropped.
  • Bring it back and watch the backlog drain.
  • Take only the database down: the error comes back from further away.
